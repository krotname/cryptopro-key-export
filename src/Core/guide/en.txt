CryptoPro Key Export — manual
==================================================================

The program copies a file-backed CryptoPro container off a supported
token, lifts the private-key export ban and writes PKCS#12 (.pfx). A
Rutoken ECP hardware key is not copied: only diagnostics and public
certificates, when present, are available for ECP. It is meant for the
owner of the keys: backup, migration or conversion.

Everything needed lives inside the exe. The only separate requirement
is CryptoPro CSP — a licensed product that cannot be embedded.

The interface is available in 20 languages: pick one in the window or
pass --lang <code>, for example CryptoProExport.exe help --lang en
This manual itself is translated into Russian and English; the other
interface languages fall back to the English text.


1. WHAT YOU NEED ON THE MACHINE
------------------------------------------------------------------
  * Windows with CryptoPro CSP installed (tested on 5.0 R2).
  * Private-key operations need a license (.jws). This machine's
    fingerprint for obtaining one is shown by the fingerprint command.
  * To read from a token — Rutoken S / Lite, JaCarta LT / PRO or ESMART.
    A Rutoken
    ECP 2.0 with a hardware non-extractable key cannot be exported
    this way: the key never physically leaves the chip.
  * Install the vendor driver/client for the exact token. It supplies
    the PC/SC reader and PKCS#11 metadata used for safe routing.
  * No helper utilities to download: p12utility and rtCOMLite are
    embedded and unpack themselves on first use.

  Check readiness: the «Refresh list» button or the command
  CryptoProExport.exe deps


2. HOW TO WORK: THE KEY IS STILL ON THE TOKEN
------------------------------------------------------------------
  1) Insert a supported token.
  2) «Refresh list» shows its type, capabilities, CryptoPro containers
     and public certificates. For Rutoken ECP this is the boundary:
     its hardware private key is not copied.
  3) Select a file-backed token row. The program asks for the folder
     to put everything into when it gets to writing files.
  4) «Make exportable» then does everything in one click:
       copies the container off the token (6 *.key files),
       extracts the certificates through CryptoAPI,
       lifts the ban on exporting the private key.
     The original token is not modified.
  5) «View container» — see its details and both key permissions.
  6) «Export to PFX» — get a .pfx with the private key.

  PIN: enter the PIN of the selected token. The program uses a factory
  PIN automatically only when the driver confirms that state:
  12345678 for Rutoken and ESMART, 1234567890 for JaCarta LT.
  One entered PIN is never sent to several readers: select an APDU row
  or use tokenexport/tokenfull with the exact reader name.
  eToken PRO (Java) / PRO also requires --container jacartapro_XX. Copy
  technical id from the [APDU ...] line printed by list. A container
  name is never used for selection; only the exact index is read.
  Global export/full are blocked before protected reads with PRO attached:
  use an addressed command or select the exact APDU row in the GUI.


3. HOW TO WORK: THE CONTAINER IS ALREADY IN A FOLDER
------------------------------------------------------------------
  No token is needed once the folder with six *.key files exists.

  1) «Install into CryptoPro» — pick the container folder. It is
     copied into the CSP store and the program verifies that
     CryptoPro really sees it. A discovered certificate is bound
     specifically to the HDIMAGE copy.
  2) «Refresh list» — the HDIMAGE copy gets its own row.
  3) «Extract certificate», then «Make exportable».
  4) «View container» and «Export to PFX».

  Without CryptoPro CSP the same is done by the exportable
  command: it verifies both keys by d·G and builds a copy of the
  container in a new folder with the export bit set in header.key
  and the MAC recomputed. The key files are carried over as is and
  the source folder is left untouched. Then install and topfx as
  usual; keyexport via p12utility remains the fallback.

  About the container name: CryptoPro matches the name against the
  contents, so renaming a copy does not always work. If it fails,
  the program restores the original name and says so — the container
  stays usable.


4. BUTTONS
------------------------------------------------------------------
  The buttons are laid out in groups; the caption on the left of each
  row says what the row is for.

  List:
    Refresh list          show the containers (CSP + tokens)
    View container        details and whether the export ban is lifted

  Steps (this is the order of the work):
    Export from token     copy an S/Lite file-backed container
    Extract certificate   save the .cer of the selected container
    Make exportable       the whole cycle for a file container
    Install into CryptoPro  put an extracted folder into the CSP store

  Result:
    Save to PFX...        build a .pfx; the dialog asks which way
    Extract key (PEM)     the private key as PKCS#8/PEM, no CSP

  Service:
    License               install a license (.jws) and verify it
    Show log              expand the log pane at the bottom
    Level: normal         filter the visible log by detail level
    Log                   open the folder with the program logs
    Language...           interface language, tooltips and messages
    Help                  this window
    Cancel                stop the operation that is running

  Level cycles through detailed, normal, warnings and errors. The session
  file always keeps every line with a DEBUG/INFO/WARN/ERROR tag.

  The log pane at the bottom starts collapsed: the status bar is
  normally enough — it shows what is running and how the previous
  step ended, and the whole window goes to the list. "Show log"
  expands the full text and remembers the height you left it at.

  Above the list there is a «Search» box: it keeps the rows where the
  typed text occurs, in any column and ignoring case. The carriers are
  not walked again — the already collected list is filtered; an empty
  box shows everything. Only one permanent field is left in the window,
  the PIN: the export asks for the destination folder itself, and the
  language is picked once with the «Language...» button.

  The list has four columns. "Location" is where the carrier is: the
  reader name, HDIMAGE, or a dash when CryptoPro sees the container but
  does not say on which device. "How it is read" is the backend: CSP,
  PKCS#11, APDU, PC/SC or rtCOMLite. Then the container name and the
  details. Clicking a header sorts by that column: ascending, descending,
  and back to the order the carriers were walked in.

  When the list holds no containers, it says why. There are three reasons:
  no carrier at all — insert one and press "Refresh list"; a carrier is
  inserted but no installed PKCS#11 library showed it — install the vendor
  drivers, and if they are already there the log has the exact reason; or
  the carrier was read and holds no containers; or the scan failed, in
  which case an empty list proves nothing and the log has the error. When the
  devices themselves are listed, the explanation sits as a strip below them.

  Every button has a tooltip — hold the cursor over it. A button that
  does not fit the selected row is greyed out, and its own tooltip
  says why.

  "Save to PFX..." offers two sources for the same compatible result.
  "Export to PFX" goes through CryptoPro's certmgr and works on the row
  selected in the list. "Build PFX (no CSP)" reads an extracted
  container folder itself and does not require CryptoPro when creating
  the file. Both files import into CryptoPro. A way that is not
  available right now is greyed out with the reason beside it.


5. COMMAND LINE
------------------------------------------------------------------
  deps                                check the dependencies
  list                                list the containers
  token [folder]                      type/capabilities/certificates
  extractcert <container> <folder>    extract the .cer
  checkexport <container>             check the export ban
  export <folder> [pin]               copy containers off tokens
  tokenexport <reader> <dir> [pin] [--container <id>]
                                      copy from the selected token
  tokenfull <reader> <dir> [pin] [--container <id>]
                                      token + all remaining steps
  keyexport <folder> <cert.cer> [pw]  lift the export ban
  exportable <folder> <new> [pw]      exportable copy (no CSP)
  install <folder> [name]             install a container into CSP
  installed                           show installed containers
  uninstall <folder>                  remove an installed container
  topfx <container> <file.pfx> [pw]   export to PKCS#12
  extractkey <folder> <file.pem> [pw] extract the key to PKCS#8/PEM (no CSP)
  extractpfx <folder> <file.pfx> <pw> build a PKCS#12 without CSP;
                                      then [container-pw] [cert.cer]
  liteexport <reader> <dir> [pin]     read a Lite container by APDU + recover
  full <folder> [cert.cer] [pin]      file-backed Rutoken S cycle
  pins                                factory PIN codes of carriers
  fingerprint                         this machine's fingerprint
  license [file|status]               install a license or show status
  help                                this manual
  --lang <code>                       interface language

  export/full do not copy a Rutoken ECP hardware private key. The
  token command remains safe diagnostics for ECP.

  Exit codes: 0 — success, 1 — bad arguments, 2 — not done in
  substance (no CSP, container not found or not visible), 3 —
  execution error.

  checkexport is more precise: 0 — all found keys are exportable,
  2 — no key was found in the container, 3 — at least one found key
  is still locked or its permissions could not be read.

  For export, full and tokenfull, code 2 means "no container was taken off".
  A partially completed full or tokenfull returns 3. For token, code 2 means
  no token was found or no certificate was available for the requested
  output folder. A script should treat only 0 as success.

  A GUI application only shows its output when it is redirected to a
  file: CryptoProExport.exe deps > deps.txt


6. IF SOMETHING GOES WRONG
------------------------------------------------------------------
  «CryptoPro CSP: NOT FOUND»
      The CSP is not installed. Without it nothing works except
      reading files off the token.

  «rtCOMLite: UNAVAILABLE» or «does not fit»
      That happens with x64/arm64 builds: the embedded library is
      32-bit and only loads into a 32-bit process. Take the regular
      portable build (x86) — it runs on x64 and on ARM64 too.

  «Devices found: 0»
      The token is not inserted, its drivers are missing, or another
      program is holding it.

  Fewer PKCS#11 devices than readers
      Not an error: readers are counted separately, and PKCS#11
      shows only the carriers that at least one installed library
      reported. The rest are listed on a PC/SC line with the vendor
      name and ATR. The reason varies: the vendor library may be
      missing entirely (as with BIFIT carriers) or present but
      failing to load or to enumerate slots — its own error is then
      written above in the same log.

  Wrong PIN, PIN locked
      The program spells such codes out in words. After several wrong
      attempts the PIN gets locked — the token administrator unlock
      code is then required.

  «key not found» when checking or exporting
      The container is not visible to CryptoPro: insert the token or
      install the container folder with «Install into CryptoPro».

  «NON-exportable»
      The ban is still in place — press «Make exportable». For a
      container taken off a token this is done on the copy in the
      destination folder, not on the token itself.

  «Container is already exportable»
      The ban does not need to be lifted again. View the container or
      continue with export to PFX.

  Logs of every run: %LOCALAPPDATA%\CryptoProExport\logs
  Passwords are never written there. That file is handy to attach to
  a question.


7. SECURITY
------------------------------------------------------------------
  An extracted container and a .pfx are your private key in the open.
  Keep them secret: on encrypted storage, with a password on the
  .pfx, and delete the working copies once they are no longer needed.

  The program is meant for an owner working with their own keys.
  No operation modifies the original token.
