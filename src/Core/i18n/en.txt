tip.refresh = Step 1. Show the list of key containers:\n  • those visible to CryptoPro CSP (including the inserted token);\n  • those found directly on connected supported tokens.\nChanges nothing — it only reads. A good place to start.
tip.export = Step 2. Copy containers from Rutoken S / Lite, JaCarta LT and ESMART into the destination folder\n(6 *.key files per container). Reads token memory directly, bypassing the CSP,\nso it works even when export is banned. The token and its data are not modified.\nThe key in the copy stays non-exportable — that is what «Make exportable» is for.
tip.extract = Step 3. Save the certificate of the container selected in the list into a .cer file\n(public data, extracted normally through CryptoAPI).\nRequires a selected container, an inserted token and the container being visible to the CSP.\np12utility needs that certificate in order to lift the export ban.
tip.full = Everything in one click: copy the containers off the token → extract the certificates →\nlift the ban on exporting the private key (p12utility --cprepair --keyexport).\nResult: the destination folder holds a copy of the container with an exportable key\n(good for a backup, for moving to another machine and for conversion to PFX).\nThe original token is not modified; the original header.key of the copy is kept as header.key.backup.
tip.check = Check the container selected in the list: has the private key export ban been lifted.\nThe program reads the key permissions (KP_PERMISSIONS) — the key itself is never exported.\nThis is how you confirm that «Make exportable» really worked.
tip.install = Install a container folder taken off a token (6 *.key files) into CryptoPro —\nthat is, copy it into the CSP store. After that the container shows up in the list and works\nwithout the token: you can extract its certificate and export it to PFX.\nRenaming is optional: CryptoPro matches the name against the container contents and\ndoes not always accept a renamed copy. The program verifies the result and tells you\nwhether the CSP actually sees the container.
tip.pfx = Export the container selected in the list into a PKCS#12 (.pfx) file — the certificate\ntogether with the private key, ready to be moved to another system.\nRequires: the export ban already lifted («Check key» reports «exportable»)\nand an installed CryptoPro CSP (its certmgr is used).\nThe program will ask for the .pfx password separately.
tip.logs = Open the folder with the program logs.\nEvery run writes its own file — handy to attach to a question\nif something did not work out. Passwords never reach the log.
tip.help = Built-in manual: where to start, what each button does,\nthe console commands and a walk-through of the usual errors.\nIt lives inside the program — no internet and no extra files needed.
tip.cancel = Interrupt the current operation.\nWork stops at the nearest step: a call into the token or a running CryptoPro\nutility has to be finished first — a running utility is killed at that point.\nFiles already saved stay where they are.
