# Рутокен S: прямое чтение файлового контейнера по APDU

Проверено 26.08.2026 на точном устройстве `VID_0A89/PID_0020`, reader
`Aktiv Co. ruToken 0`, PKCS#11 model `Rutoken S`, firmware 36.0. Серийный
номер и постоянные пользовательские данные в документе не сохраняются.

## Почему не rtCOMLite

На непустом Рутокен S старый COM-компонент оказался непригоден для production:

- поштучный файловый обход возвращал `Unsupported function`;
- `EnumFolders()`/`EnumFiles()` через SAFEARRAY повреждали кучу процесса
  (`0xC0000374`), что невозможно безопасно перехватить в .NET.

Поэтому `RutokenSApdu` читает карту напрямую через PC/SC. Метаданные и `name.key`
перечисляются без PIN; защищённые ключевые файлы читаются только после `VERIFY`.
После операции права сессии сбрасываются командой `RESET ACCESS RIGHTS`.

## Файловая раскладка

На синтетическом двухключевом контейнере дерево имело вид:

```text
/3F00/0000/0000/0002/0A00/
  0A06  name.key
  0A03  header.key
  0A02  primary.key
  0A01  masks.key
  0A05  primary2.key
  0A04  masks2.key
```

Суффиксы файлов постоянны, старший байт соответствует каталогу контейнера.
Production-код не привязан к пути `0A00`: дерево обходится с ограничениями глубины
и числа узлов, а контейнер принимается только при наличии `name.key`, `header.key`
и хотя бы одной полной пары `primary` + `masks`.

Основные команды — ISO 7816 SELECT PATH/SELECT FILE и READ BINARY. Размер EF берётся
из FCP tag `80` как little-endian. PIN передаётся только в `VERIFY` (`00 20 00 02`),
не пишется в журнал и не подбирается.

## Физический E2E

На токене создан отдельный двухключевой контейнер КриптоПро. До чтения:

- обмен: `KP_PERMISSIONS=0x00130898`;
- подпись: `KP_PERMISSIONS=0x00122898`;
- `CRYPT_EXPORT=0x4` отсутствовал у обеих пар.

Публичная команда `tokenfull` прочитала шесть файлов (после помещения сертификатов:
`name.key` 13 байт, `header.key` 1257 байт, обе `primary` по 70 байт и обе `masks`
по 56 байт), извлекла два сертификата и успешно выполнила `p12utility --cprepair`.

Точная HDIMAGE-копия после ремонта показала `0x0013089C` и `0x0012289C`.
Обменный PFX выгружен штатным `certmgr` и принят `certutil -dump`. Соседний
Рутокен ЭЦП `VID_0A89/PID_0030` не участвовал ни в одной записывающей операции.

## Источник профиля карты

Команды SELECT/LIST/READ и little-endian поля сверены с открытой реализацией
[OpenSC card-rutoken.c](https://github.com/OpenSC/OpenSC/blob/master/src/libopensc/card-rutoken.c).
