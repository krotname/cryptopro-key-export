# Реестр заводских PIN-кодов носителей

Значения опубликованы самими производителями и одинаковы для всей партии, пока владелец не
сменил PIN. Реестр нужен по двум причинам: владелец обычно PIN не менял и вводит одно и то же
вручную, а разработчику нужен один источник правды вместо констант, рассыпанных по коду.

Источник правды в коде — [`src/Core/StandardPins.cs`](../src/Core/StandardPins.cs)
(Windows) и `core/src/main/kotlin/name/krot/cryptoexport/core/StandardPins.kt` в
[Android-порте](https://github.com/krotname/cryptopro-key-export-android). Таблица ниже —
человекочитаемая копия; при расхождении верен код.

## Где значения применяются

- `DirectTokenApdu.ResolvePin` и `ExportPipeline.ResolveLitePin` — авто-PIN для APDU-путей.
- GUI (`MainForm.SuggestFactoryPin`) — подстановка в поле «PIN» после опроса токенов.
- CLI `cryptoexport pins` — печать всего реестра со ссылками на источники.

Подстановка ограничена намеренно: значение попадает только в поле ввода, отправка PIN на карту
остаётся явным действием пользователя. Правило подстановки (`StandardPins.SuggestFor`) узкое:

- подключён **ровно один** носитель — при двух и более выбранной может оказаться строка того,
  чей PIN уже сменён;
- драйвер подтверждает заводское состояние PIN (`PinDefault`, флаг PKCS#11
  `CKF_USER_PIN_TO_BE_CHANGED`) при чистом счётчике попыток (`PinCountLow`/`PinFinalTry`/`PinLocked`
  сняты);
- модель допускает подстановку (см. столбец «Подстановка»);
- поле пустое — введённое пользователем не затирается, а собственное подставленное значение
  снимается при каждом обновлении списка носителей.

Само подставленное значение при этом **не считается явным вводом**: пока пользователь его не
изменил, операция получает `null`, и PIN выбирает `DirectTokenApdu.ResolvePin` по актуальным
флагам носителя. Так горячая замена токена в том же считывателе (без нажатия «Обновить») не может
отправить заводское значение на носитель со сменённым PIN. Отредактированный текст перестаёт
совпадать с подставленным и идёт дальше как обычный явный PIN.

Перед самой операцией состояние выбранного носителя перечитывается (`MainForm.CurrentStateOf`):
строка списка несёт снимок прошлого обновления, а токен могли заменить в том же считывателе.
Смена серийного номера отмечается в журнале; если перечисление недоступно, работа идёт по
прежнему снимку — как и до появления подстановки.

Причина строгости простая: неверный PIN расходует попытку — третья подряд блокирует носитель, и
разблокировать его можно только PIN Администратора.

Примечания к записям хранятся ключами локализации (`pins.note.*`), поэтому `pins --lang en`
печатает их на языке интерфейса; русский текст в таблице выше — просто перевод этих ключей.
