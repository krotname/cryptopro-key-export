# Проверка подключённых токенов — 09.09.2026

**Полный аппаратный E2E не завершён.** Экспорт закрыт отсутствующей лицензией CryptoProExport. Доступ к PC/SC восстановлен выбором административной SSH-сессии на том же сервере: два последовательных csptest увидели все 7 карт, команда token завершилась с кодом 0. Служба не перезапускалась. Создание синтетических контейнеров, снятие запрета, HDIMAGE, PFX и проверка подписи в этом прогоне не выполнялись.

## Продолжение после уточнения владельца

Владелец разрешил самостоятельный выпуск лицензии через свой license-server. Репозиторий krotname/license-server клонирован, штатный keytool собран задачей :keytool:fatJar (BUILD SUCCESSFUL). В GitHub Secrets репозитория ключ активации не найден. Приложение доверяет ключу cryptoexport-2026; новый произвольный ключ вместо него не внедрялся.

Сейф Vaultwarden открылся через закреплённое окно Chrome. Сохранённый вход a@krot.name принят, затем сервер потребовал физический ключ безопасности. Подтверждение не получено, попытка закончилась таймаутом аутентификации. Лицензия из сейфа и приватный ключ активации ещё не получены. Лицензия КриптоПро CSP — отдельная от лицензии CryptoProExport.

Административный SSH на ADLER-WHITE-W1 под KRT подтвердил IsAdmin=True. Через него PC/SC работает, тогда как текущая RDP-сессия получала 0x8010001D. Это уточняет исходный блокер: неисправность самой службы не доказана. Перезапуск из локального процесса был отклонён правами доступа, состояние службы не менялось.

В административном token-опросе библиотека вернула C_GetTokenInfo → CKR_GENERAL_ERROR. Программа ошибочно добавила пустую запись и сообщила нормальное состояние PIN. Исправлено: без успешно прочитанных метаданных запись не добавляется и не подавляет повторное чтение другим драйвером. Регрессия проверена для отсутствующего, пустого и непустого reader; после отказа другой драйвер может добавить достоверную запись с PinLocked=true.

## Исправление

cli.pcsc.hint ошибочно утверждал, что карта вне выдачи установленных библиотек «не является PKCS#11-токеном». Живой Feitian SCR301 показал такой сценарий: карта и ATR доступны через PC/SC, но библиотека карту не показала. Опрос не различает отсутствие драйвера, неподдержанную модель и сбой сессии.

Исправлены все 20 переводов: теперь сообщается только отсутствие карты в выдаче установленных библиотек и предлагается проверить драйвер и поддержку модели. Отсутствие в списке не доказывает невозможности экспорта. APDU-допуски не расширены.

ESMART Nano 192K отклонён allowlist профилей; новый протокол без аппаратных доказательств не добавлялся. Причина пропадания PC/SC не установлена: одинаковый отказ приложения и csptest подтверждает проблему доступа окружения, но не её источник.

## Для завершения

1. Установить действительную лицензию штатной командой license для этой машины/профиля.
2. Использовать подтверждённый административный SSH-контекст для аппаратных опросов; повторно снять baseline непосредственно перед E2E.
3. Идентифицировать точные носители и известные PIN без подбора.
4. Пройти [runbook](../runbooks/token-e2e.md) на собственных уникальных синтетических контейнерах: CRYPT_EXPORT до/после, обе ключевые ветви, HDIMAGE, PFX, подпись, уборка только своих объектов.
5. Для активных и неподдержанных профилей проверить ожидаемый отказ отдельно: отказ лицензии не доказывает аппаратную неизвлекаемость.

Пользовательские контейнеры, PIN, сертификаты и закрытые ключи не изменялись и не экспортировались. Отчёт не содержит имён владельцев контейнеров и секретов.
