# Рутокен ЭЦП fw 23.02: точная инвентаризация и граница экспорта

Дата проверки: 21 августа 2026 года. Цель: собственный USB-носитель
`VID_0A89&PID_0030`, точный PC/SC reader `Aktiv Rutoken ECP 0`. Серийный номер,
метки объектов, сертификаты и сырые дампы здесь намеренно не публикуются.

## Что проверено без изменения носителя

- PnP: устройство исправно, штатный Microsoft Usbccid/WUDF; служба PC/SC
  работает. Одновременно были подключены четыре разных USB-токена.
- PC/SC перечислил три исправных reader: целевой Rutoken ECP, JaCarta LT и
  ESMART USB64K. На первоначальном baseline четвёртый ESMART имел transient
  `Code 10` и в PC/SC отсутствовал; позднее в тот же день его восстановили.
  Это наблюдение описывает только исходный момент, а не текущий статус
  устройства.
- Подключение `SCardConnect` выполнялось только по точному имени reader,
  в shared/read-only режиме. Карта отвечает по T=1; ATR распознан как
  семейство Rutoken, но ATR не использовался для вывода о поколении.
- Использована системная `rtPKCS11ECP.dll` 2.18.0.0 с действительной подписью
  Aktiv-Soft. Более старая копия 2.17.4.0 из RutokenControlCenter не подменяла
  системную библиотеку.
- `CK_TOKEN_INFO`: manufacturer `Aktiv Co.`, model `Rutoken ECP`, hardware
  `20.05`, firmware `23.02`. Токен и пользовательский PIN инициализированы;
  требуется login; protected authentication path отсутствует.
- Заводской PIN-флаг был установлен, а `COUNT_LOW`, `FINAL_TRY` и `LOCKED` —
  сняты. Эти флаги читаются без PIN и не расходуют попытки.

## Профиль механизмов PKCS#11

Повторное read-only перечисление без login вернуло 45 механизмов. Для
относящихся к профилю механизмов прочитан `CK_MECHANISM_INFO`:

| Возможность | Наблюдение |
|---|---|
| RSA key generation/sign/encrypt | аппаратно, максимум 2048 бит |
| ГОСТ key generation/sign | аппаратно |
| `CKM_EC_KEY_PAIR_GEN`, ECDSA | отсутствуют |
| SHA/MD5 digest | объявлены как software |

Это **профиль возможностей ЭЦП 2.x**, а не доказательство модели или поколения.
Официальная таблица отличает ЭЦП 3.0 наличием EC keygen/ECDSA, но USB PID 0030
используется несколькими поколениями, а model/ATR сами по себе неоднозначны.

## Объекты и единственный login

До login в public read-only session найдено 0 объектов. После проверки
заводского PIN-флага и чистого счётчика был выполнен ровно один login в
read-only session; после него также найдено 0 объектов и 0 private keys.
`CKA_VALUE` не запрашивался, затем выполнен logout. PIN-флаги после операции
не изменились.

Из-за отсутствия объекта закрытого ключа на этом экземпляре нельзя измерить
его `CKA_SENSITIVE`, `CKA_EXTRACTABLE` и `CKA_NEVER_EXTRACTABLE`. Поэтому эти
атрибуты не приписываются текущему токену по аналогии с другим экземпляром.

## Одновременные устройства и маршруты приложения

- `deps`, `list` и `token` видят целевой Rutoken и JaCarta независимо; сбой
  четвёртого USB-устройства на первоначальном baseline не создавал ложный
  PC/SC reader.
- Точный reader `Aktiv Rutoken ECP 0` классифицируется как smart-card ECP и
  передаётся в `SmartCardReaders`, поэтому опасный файловый обход rtCOMLite
  для него пропускается. JaCarta/ESMART также не должны попадать в этот обход.
- Базовая семантика `Aktiv ruToken 0` сохранена для Rutoken S: без отдельного
  живого доказательства её нельзя менять в узком PR про ECP.
- Глобальный `csptest -enum_cont -fqcn` при таком наборе устройств завис на
  90 секунд без вывода. Процесс был остановлен. Этот глобальный маршрут не
  повторяется и не считается доказательством состояния целевого reader.

## Пользовательская граница

Приложение не копирует аппаратный закрытый ключ Рутокен ЭЦП и не обещает
снять для него запрет на экспорт. Для ECP доступны read-only диагностика и
сохранение публичного сертификата, если такой PKCS#11-объект присутствует.
Пустой текущий экземпляр не даёт ни сертификата, ни per-object доказательства
неизвлекаемости.
