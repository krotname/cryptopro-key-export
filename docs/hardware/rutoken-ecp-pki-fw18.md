# Рутокен ЭЦП PKI (fw 18.0): отрицательный E2E по построению

Дата проверки: 3 сентября 2026 года. Проверен собственный расходный тестовый
носитель. Модель по данным владельца — **Рутокен ЭЦП PKI** (партия «Рутокен ЭЦП PKI
новые 3 шт»); это отдельный SKU семейства Рутокен ЭЦП, отличный от уже покрытого
USB-токена Рутокен ЭЦП 2.0 (fw 23.02) и от ЭЦП 3.0 (fw 30.02). Серийный номер, PIN и
содержимое синтетического контейнера намеренно не сохраняются.

Носитель активный: закрытый ключ генерируется и используется внутри чипа —
неизвлекаемость ключа и есть назначение PKI-токена. Доказано **построением** (memory
`prove-negatives-by-construction`): на самом токене создан свой синтетический
неэкспортируемый ГОСТ-контейнер, после чего показано, что CSP не может скопировать
закрытый ключ с носителя, а приложение честно отказывает.

## Точная идентификация

| Признак | Проверенное значение |
|---|---|
| Модель (по данным владельца) | **Рутокен ЭЦП PKI** (USB-токен) |
| PC/SC reader | `Aktiv Rutoken ECP 1` (второй считыватель; первый `Aktiv Co. ruToken 0` пуст) |
| USB | `USB\VID_0A89&PID_0030` (REV_0100), перечисляется как Microsoft Usbccid (WUDF) |
| BusReportedDeviceDesc | `Rutoken ECP` |
| ATR | `3B 8B 01 52 75 74 6F 6B 65 6E 20 44 53 20 C1` («Rutoken DS») |
| PKCS#11 module | системная `rtPKCS11ECP.dll` |
| PKCS#11 model / label | `Rutoken ECP` / `<нет>` |
| firmware / hardware | `18.0` / `54.01` |
| механизмы | 35, профиль как у Рутокен ЭЦП 2.x |
| CSP-провайдер | 80 (ГОСТ Р 34.10-2012, 256 бит) |
| PIN | заводской (флаг подтверждён приложением) |
| память | 64 КБ, свободно 60 КБ |

Возможности по PKCS#11: RSA HW keygen до 2048 бит, ECDSA HW отсутствует, ГОСТ HW
присутствует. ГОСТ-путь CSP работает — на нём и построен отрицательный тест.

**Форм-фактор из ярлыка приложения не выводится.** Метка `Рутокен ЭЦП (смарт-карта)`
в выводе `list`/`token` — это фиксированная подпись всего семейства ЭЦП
(ключ `kind.rutoken.ecp`, метод `Pkcs11Token.KindName`), одинаковая для любого носителя
ЭЦП, а не измеренный форм-фактор. Рутокен ЭЦП PKI — USB-токен; физический корпус в
этом сеансе отдельно не фотографировался.

**Поколение из fw/ATR/PID по отдельности не выводится** (тот же принцип, что в
[rutoken-ecp-fw23.md](rutoken-ecp-fw23.md): ATR `Rutoken DS` и PID `0030` общие у
ЭЦП 2.0/3.0/PKI). Отнесение к профилю **2.x** опирается на два независимых наблюдения:

- набор из 35 механизмов диагностирован приложением как «механизмы как у ЭЦП 2.x»;
- CSP обслуживает носитель как обычный ГОСТ-контейнер, **не как ФКН**: создание
  ключей прямо на токене (`-newkeyset`) проходит, а `keycopy` даёт
  `NTE_BAD_KEY_STATE`, а не `NTE_NOT_SUPPORTED`, которым ЭЦП 3.0 отвечает на путь
  «диск→токен» (AGENTS.md, пп. 23, 27).

Отличительные аппаратные маркеры от уже покрытого Рутокен ЭЦП 2.0 (fw 23.02, hw
20.05, 46 механизмов): **SKU PKI, fw 18.0, hw 54.01, 35 механизмов.**

## Исходное состояние (baseline)

`csptest -keyset -enum_cont -verifycontext -fqcn` до прогона показал только четыре
боевых контейнера владельца на `HDIMAGE` и ни одного `cpxt_*`. Тег `cpxt_rec18`
зарезервирован во всех пространствах имён (токен, `HDIMAGE`, «Личное») — свободен.

## Синтетический контейнер на токене

```
csptest -keyset -newkeyset -container "\\.\Aktiv Rutoken ECP 1\cpxt_rec18" \
        -provtype 80 -password <PIN> -protected=none
```

Созданы обе пары (signature + exchange) **прямо на носителе**, аппаратным ДСЧ;
свободная память чипа уменьшилась 60 КБ → 57 КБ. Обе пары неэкспортируемы:

| Ключ | `KP_PERMISSIONS` | Флаг `CRYPT_EXPORT` |
|---|---|---|
| обмен | `0x00130898` | отсутствует |
| подпись | `0x00122898` | отсутствует |

Это корректный baseline «…98»: запрет на экспорт установлен политикой, экспортируемого
образца, который CSP скопировал бы с любого носителя, здесь нет.

## Аппаратная граница (ядро отрицательного доказательства)

Копирование контейнера с токена на диск средствами CSP:

```
csptest -keycopy -contsrc "\\.\Aktiv Rutoken ECP 1\cpxt_rec18" \
        -contdest "\\.\HDIMAGE\cpxt_rec18" -typesrc 80 -typedest 80 -pinsrc <PIN> -silent
```

Результат — отказ на переносе закрытого ключа:

```
[ErrorCode: 0x8009000b]
keycopy.c:331: CopyPrivateKey(AT_KEYEXCHANGE)
Error 0x8009000b: Ключ не может быть использован в указанном состоянии.
```

`0x8009000b` (`NTE_BAD_KEY_STATE`) на `CopyPrivateKey` означает, что закрытый ключ
физически не покидает чип: у него нет `CRYPT_EXPORT`, и он аппаратно неизвлекаем.
На `HDIMAGE` при этом **не создаётся** даже пустой набор ключей (последующий
`deletekeyset "\\.\HDIMAGE\cpxt_rec18"` вернул `0x80090016` «набор ключей не
существует»).

## Поведение приложения (fail-closed)

Файлового APDU-пути для этого носителя приложение не предлагает: в выводе `list`
строка контейнера идёт **без** префикса `[APDU …]`, а прямая попытка экспорта
завершается честным отказом без единого записанного файла:

```
tokenfull "Aktiv Rutoken ECP 1" <папка> <PIN>
→ EXIT=3
  ОШИБКА: Носитель «Aktiv Rutoken ECP 1» не подходит для этой команды:
  Рутокен ЭЦП (смарт-карта). Выберите поддерживаемый носитель — список даёт команда list.
```

Маршрутизация уже корректна: `DirectTokenApdu.Supports` не включает
`RutokenKind.RutokenEcp`, а классификация `Rutoken ECP → RutokenEcp` покрыта тестом
`Pkcs11TokenTests.Classify_MapsModelToFamily`. **Изменений кода не потребовалось.**

## Уборка и независимый readback

- контейнер снят с токена: `csptest -keyset -deletekeyset -container
  "\\.\Aktiv Rutoken ECP 1\cpxt_rec18" -provtype 80 -password <PIN>` → `Container …
  deleted`, код 0, PIN-диалог не потребовался (как у Рутокен S/Lite);
- на `HDIMAGE` копии не было (`0x80090016`); сертификата `CN=cpxt_rec18` в «Личном»
  нет;
- `enum_cont` после прогона совпал с baseline (те же четыре боевых контейнера);
- `checkexport "\\.\Aktiv Rutoken ECP 1\cpxt_rec18"` → код 2 «контейнер не найден»
  при **живом** ридере (виден в PKCS#11, свободная память вернулась к 60 КБ) —
  контейнер действительно снят, а не считыватель «онемел» (AGENTS.md, п. 31).

## Пользовательская граница

Для Рутокен ЭЦП PKI результат закрыт как **полностью отрицательный**: аппаратный
закрытый ключ можно создать и использовать на чипе, но нельзя скопировать на диск.
Это свойство активного PKI-носителя, а не недостающая команда CryptoProExport.
Приложение предоставляет диагностику и выгрузку публичного сертификата, если он
существует, но резервной копии закрытого ключа для этой модели не обещает.
