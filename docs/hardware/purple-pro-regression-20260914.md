# Регрессия двух одновременно подключённых eToken PRO

Проверено 14.09.2026 на Windows 11, CryptoPro CSP 5.0.13800, x86.
Сборка v1.9.0; лицензия продукта действующая. Операции выполнялись только
на двух расходных токенах и созданных для этого прогона контейнерах.

Серийные номера сверялись перед аппаратными операциями. Одновременно присутствующий
YubiKey исключён из операций. Инициализация и форматирование не потребовались;
актуальные PIN проверены и сохранены в Vaultwarden, счётчики попыток в норме.

## Подтверждённые дефекты

1. Пустой публичный слот PRO давал DER_TAG. Интегрирован PR #107:
   нулевой payload name.key пропускается, повреждённый непустой DER остаётся ошибкой.
2. p12utility возвращала успех, но разделённая PRO-копия не сохраняла исходные
   пары и не проходила установку сертификата. Теперь tokenfull использует
   ExportableContainerBuilder: обе пары сохраняются в одной папке, первичные
   файлы и маски не переписываются, проверяются флаги и MAC заголовка.
3. Обменный разбор мог принять подписную пару из второго ciphertext: раньше
   подходил любой сертификат или отпечаток заголовка. Теперь поля [10] и [11]
   проверяются по назначению пары, даже если другой сертификат математически подходит.
4. Подписной PFX без CSP использовал обменный ALG_ID и keyUsage, из-за чего CSP
   отклонял импорт. Эталонный подписной PFX CSP содержит ALG_ID 0x2E49 и BIT STRING
   03020780; обменный — 0xAA46 и 030205A0. Оба варианта защищены регрессией.
5. Тесты тайм-аута и отмены rtCOMLite зависели от запуска дочернего процесса
   за 250 мс. Отмена теперь следует за подтверждённым стартом, тайм-аут учитывает
   запуск; оба теста проверяют фактическое завершение дочернего процесса.

## Доказательство результата

На каждом токене создан синтетический контейнер с двумя разными ключами
ГОСТ 2012-256 и отдельными самоподписанными сертификатами. После tokenfull
и install обе пары подписали контрольные данные; SHA-256 публичных ключей
и сертификатов совпали с исходными парами. Оригиналы остались неэкспортируемыми.

Проверены восемь PFX: два токена × две пары × два способа экспорта. Каждый
прошёл PFXVerifyPassword, отклонение неверного пароля и временный импорт
PFXImportCertStore(PKCS12_NO_PERSIST_KEY), после которого выполнены подпись
и её проверка. KeySpec и сертификат сверены с соответствующей исходной парой.
Вторую пару экспортировали через production API, поскольку CLI выбирает обменную.
BouncyCastle Pkcs12Store.Load не понимает CryptoPro PBE .1.80; его отказ
не трактуется как дефект PFX, пригодность проверена целевым CryptoPro.

Десять отрицательных сценариев: пропущенный, неполный, неизвестный и видимый
вместо технического selector отклонены с кодом 1 на обоих токенах без создания
выходной папки; неверный reader — код 2. Шесть последовательных инвентаризаций
при двух подключённых устройствах завершились без ошибок и смешения слотов.

PR #107 также добавляет backend ESMART Nano 192K/ГОСТ и исправляет адресацию
ГОСТ-слотов. Их аппаратные проверки описаны в протоколах 10.09.2026; данный
прогон подтверждает сборку и программные регрессии этих изменений.
