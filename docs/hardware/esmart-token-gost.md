# ESMART Token ГОСТ (MIK51): полный аппаратный E2E

Проверено 02.09.2026 на собственном расходном носителе. Тест включал создание
синтетического неэкспортируемого контейнера, снятие его по APDU, снятие запрета на
экспорт и итоговую очистку. Полный серийный номер, PIN и ключевой материал в
репозитории не сохраняются (серийник частично виден на фото-наклейке — это признак
модели, а не секрет).

## Итог

ESMART Token ГОСТ — **пассивный CSP-носитель**: закрытый ключ ГОСТ (`primary`+`masks`)
сходит с карты открытым текстом через файловые READ BINARY, как у прочих ESMART и
JaCarta LT. `CryptoProExport` снимает контейнер по PC/SC APDU мимо CSP, помечает ключи
экспортируемыми и проходит полный цикл до PFX. Это подтверждено и независимо —
трассировкой штатного `csptest` winscard-прокси (`docs/apdu/harness`): те же файлы
контейнера читаются открытым текстом.

Поддержка добавлена отдельным backend `EsmartGostApdu` (не старый `EsmartApdu`):
файловая раскладка и путь доступа у ГОСТ-платформы другие (см. ниже).

## Точное устройство и окружение

| Признак | Значение |
|---|---|
| PC/SC reader | `Feitian SCR301 0` — **универсальный CCID-считыватель** |
| USB (ридер) | `VID_096E/PID_0503` (Feitian) |
| ATR | `3B 7C 95 00 00 45 53 4D 41 52 54 47 4F 53 54 31 30` (ASCII-хвост `ESMARTGOST10`) |
| PKCS#11 model | `ESMARTToken GOST` |
| PKCS#11 manufacturer | `ISBC` |
| PKCS#11 label | `ESMART Token GOST` |
| Платформа | MIK51 (`80 06 03 00 20` → `MIK51GH…TRUST_2.05_S`), 72 КБ, свободно 56 КБ |
| Провайдер CSP | Crypto-Pro GOST R 34.10-2012 (провайдер 80, ключи 256 бит) |
| Заводской PIN | `12345678` |
| Протокол | T=1 |

**Считыватель универсальный.** В отличие от эксклюзивных `ISBC ESMART Token 0` и
`ESMART Token USB 64K 0`, имя `Feitian SCR301 N` ничего не гарантирует — в него можно
вставить любую смарт-карту. Поэтому допуск к APDU требует **точную пару model/manufacturer
PKCS#11 и live ATR** (аналогично eToken PRO), а сессия открывается с проверкой ATR. См.
`EsmartApdu.IsExactGostMetadata` / `IsExactLiveGostReader` и маршрутизацию в
`DirectTokenApdu` по `EsmartApdu.IsGostReader`.

## Файловая раскладка (отличается от старого ESMART)

Подтверждена трассировкой `csptest` и ручным replay winscard:

1. `SELECT MF` (`00 A4 00 00 02 3F 00`);
2. `SELECT` апплетов `F0 49 53 42 43 44 48 00` (ISBCDH; полный APDU
   `00 A4 04 00 08 F0 49 53 42 43 44 48 00` — хвостовой `00` обязателен, 7-байтный AID
   даёт `6A82`) и `F0 49 53 42 43` (ISBC) — они ставят контекст чтения;
3. контейнер выбирается по пути `8F01/7F0X` (`00 A4 08 00 04 8F 01 7F 0X`);
4. ключевые EF лежат плоско в текущем контейнере как `F011…F016`, обычным DER (без
   служебного префикса `01`, добито нулями до размера файла);
5. чтение открывает `VERIFY PIN` по ссылке `0x83`.

Суффиксы 1..6 идут подряд: `01`=masks, `02`=primary, `03`=header, `04`=masks2,
`05`=primary2, `06`=name (у старого ESMART вторая пара — на `0x11/0x12`, а контейнеры —
слоты `F100…F900` под `7F01`). Одна папка на контейнер, обе пались вместе.

## Полный цикл, что проверено

Синтетический контейнер `cpxt_esg` создан КриптоПро CSP прямо на токене (обе пары
неэкспортируемы, baseline `KP_PERMISSIONS` без `CRYPT_EXPORT`: обмен `…0898`, подпись
`…2898`), с двумя самоподписанными тестовыми сертификатами.

1. `list` — контейнер виден по APDU: `[APDU esmartgost_7F01] cpxt_esg`.
2. `tokenfull` — APDU прочитал шесть файлов (`name/header/primary/masks/primary2/masks2`),
   извлёк оба сертификата, `p12utility --cprepair --keyexport` пометил ключи
   экспортируемыми. Токен только читался.
3. `install` → HDIMAGE-копия; `checkexport \\.\HDIMAGE\cpxt_esg` — **обе пары `…9C`**:
   обмен `0x0013089C`, подпись `0x0012289C`. Запрет на экспорт снят.
4. PFX собран обоими путями: `extractpfx` (для OpenSSL — GOST-ключ присутствует) и
   `topfx` через `certmgr` (для КриптоПро, провайдер Crypto-Pro GOST R 34.10-2012).

## Очистка

Удалено только своё: контейнер с токена (`csptest -deletekeyset` — показывает диалог
«Аутентификация — КриптоПро CSP», PIN вводится SendInput/SendKeys, как у прочих ESMART),
HDIMAGE-копия, оба сертификата `CN=cpxt_esg` из «Личное», рабочая папка. Приёмка:
`checkexport` целевого контейнера вернул код 2 (носитель жив в PKCS#11, память
50→56 КБ — контейнер физически снят), `enum_cont` совпал с baseline.

## Границы

Проверено именно снятие файлового контейнера программного КриптоПро CSP. Отдельная
аппаратная PKCS#11-пара ESMART (`CKA_NEVER_EXTRACTABLE`) утилитой не извлекается — это
другой класс объектов; здесь он не тестировался, но архитектурно совпадает с прочими
ESMART (ГОСТ-контейнер обслуживает CSP, а не универсальный аппаратный PKCS#11-объект).
